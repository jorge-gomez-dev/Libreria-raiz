# \# Librería Independiente Raíz 📚

# 

# \*\*Historias que conectan con nuestras raíces.\*\*

# 

# \## Propósito

# 

# Sitio web estático de una librería independiente. Presenta su identidad, recomienda libros y ofrece espacios de contenido y contacto para la comunidad lectora. Proyecto académico desarrollado con HTML5, CSS3 y JavaScript.

# 

# \## Funcionalidades

# 

# \- Presentación y filosofía de Librería Raíz.

# \- Catálogo de recomendaciones con portadas.

# \- Blog con artículos y reseñas editoriales de muestra.

# \- Agenda de actividades literarias propuestas.

# \- Formulario de contacto con validación en el navegador.

# 

# \*\*Alcance del formulario:\*\* esta versión valida los campos en el navegador y muestra una confirmación local. No transmite ni almacena datos. Para recibir mensajes reales se necesita integrar un servicio de formularios o un backend.

# 

# \*\*Alcance de la agenda:\*\* las actividades son propuestas académicas. Fechas, horarios y lugares están pendientes de confirmación y no deben anunciarse como eventos reales.

# 

# \## Tecnologías

# 

# \- HTML5: estructura y contenido semántico.

# \- CSS3: identidad visual y diseño adaptable.

# \- JavaScript: validación del formulario.

# \- Git y GitHub: control de versiones y colaboración.

# \- GitHub Pages: publicación del sitio estático.

#

# \## Ejecución local

# 

# 1\. Clonar el repositorio o descargar el ZIP.

# 2\. Abrir la carpeta del proyecto.

# 3\. Abrir `index.html` en un navegador actualizado.

# 4\. Probar navegación, imágenes, blog, agenda y validación del formulario.

# 

# No se requieren dependencias ni servidor para esta versión estática.

# 

# \## Colaboración: GitHub Flow

# 

# 1\. Actualizar `main` antes de iniciar una tarea.

# 2\. Crear una rama por funcionalidad o corrección.

# 3\. Hacer cambios pequeños y relacionados.

# 4\. Registrar commits con Conventional Commits.

# 5\. Abrir un Pull Request hacia `main`.

# 6\. Solicitar revisión de otro integrante y resolver observaciones.

# 7\. Fusionar el Pull Request y comprobar GitHub Pages.

# 

# \### Convención de ramas

# 

# \- `feat/blog-resenas`

# \- `feat/calendario-eventos`

# \- `feat/formulario-contacto`

# \- `fix/estructura-html`

# \- `docs/actualizar-readme`

# 

# \### Conventional Commits

# 

# Formato: `tipo(alcance): descripción breve`

# 

# \- `feat:` nueva funcionalidad.

# \- `fix:` corrección de errores.

# \- `docs:` documentación.

# \- `style:` cambios visuales sin alterar lógica.

# \- `refactor:` reorganización interna sin cambiar comportamiento.

# 

# Ejemplos de mensajes propuestos para este sprint:

# 

# ```text

# fix(html): corregir cierre de secciones

# feat(blog): agregar sección de reseñas

# feat(eventos): crear agenda de actividades

# feat(contacto): validar formulario en navegador

# docs(readme): documentar instalación y flujo git

# ```

# 

# \## Prevención y resolución de conflictos

# 

# Antes de trabajar, cada integrante comunica los archivos que modificará. Se recomienda que cada rama atienda una sola tarea y evitar ediciones simultáneas del mismo bloque. Ante un conflicto, actualizar la rama, comparar las versiones, conservar los cambios válidos, ejecutar pruebas locales y solicitar revisión antes de fusionar.
